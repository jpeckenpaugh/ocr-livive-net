Why Browser-Native OCR From Scratch?

Modern machine learning is often wrapped inside gigabytes of framework runtimes (PyTorch, TensorFlow, libtorch) and hidden behind autograd engines. This project demonstrates that character recognition on real-world handwritten digits can be executed from first principles in clean Rust, compiled directly to WebAssembly, and audited by hand with paper and pencil.

The Dataset: MNIST

The MNIST database (Modified National Institute of Standards and Technology) is the gold standard benchmark in pattern recognition. Originally assembled by Yann LeCun, Corinna Cortes, and Christopher Burges, it consists of 70,000 28×28 grayscale images of handwritten digits extracted from Census Bureau employees and high school students.

The Pipeline: 28×28 Normalization

When you draw on the canvas above, it executes the identical preprocessing pipeline designed for MNIST:

  1. Grayscale conversion via integer arithmetic: (299·R + 587·G + 114·B + 500) / 1000.
  2. Bounding-box extraction of ink pixels, expanded symmetrically into a square.
  3. Box-filter resampling to a 20×20 bounding box with half-up rounding.
  4. Center of mass translation positioning the centroid of ink at coordinates (14, 14) within the 28×28 canvas.

The Progression of Transparency

  • Centroid (Average): The most naive model. Averages each digit class into a single prototype image. Unconditional baseline.
  • k-NN (Memorize): The model is the dataset. No parameters; pure geometric neighborhood comparison.
  • Perceptron (Linear separation): A single affine hyperplane per class. Visualizable as a spatial weight template.
  • MLP (Non-linear representation): Adds a hidden layer with ReLU activation. Capable of learning stroke combinations and curvature.

How to Run in Python (onnxruntime)

import onnxruntime as ort
import numpy as np

# Load model
session = ort.InferenceSession("mlp.onnx")

# Query shape: [1, 784] float32 pixels in range 0..255
dummy_input = np.zeros((1, 784), dtype=np.float32)
outputs = session.run(None, {"input_pixels": dummy_input})

probabilities = outputs[0]  # shape: [1, 10]
predicted_digit = np.argmax(probabilities)
print("Predicted digit:", predicted_digit)

Centroid Classifier Details

Intuition & Model Architecture

The centroid classifier computes the arithmetic mean image for each of the 10 digit classes. At inference time, it computes the Euclidean distance between the unknown image and each of the 10 prototype images.

d_c = √( Σ (x_i - μ_{c,i})² )
prediction = argmin_c(d_c)

Why it fails

A single mean cannot represent multimodal digit styles (e.g., a "7" with a European crossbar vs. an American plain "7"). Taking the mean blurs contradictory features together.

k-Nearest Neighbors (k=3) Details

Intuition

k-NN has zero training time: the model is literally the dataset. For an input image, it searches through all N training samples, identifies the 3 closest images under Euclidean distance, and awards the prediction to the majority vote.

D(x, y) = √( Σ (x_i - y_i)² )
prediction = majority_vote(top_k(D))

Resource Tradeoff

Fast to train (instant copy), but inference cost scales linearly as O(N · 784). For 60,000 samples, every single prediction requires calculating 47 million pixel subtractions!

Multiclass Perceptron Details

Intuition & Math

A single linear layer mapping 784 inputs directly to 10 class logits, followed by numerically stable Softmax normalization.

z_c = b_c + Σ w_{c,i} · (x_i / 255)
p_c = exp(z_c - max(z)) / Σ exp(z_j - max(z))
Loss = -log(p_{true})

Weight Interpretation

Each digit class has a 28×28 weight template. Positive weights (orange) reward ink in expected stroke locations; negative weights (blue) penalize ink in areas that would distinguish it from other digits (e.g. ink across the center loop of an 8).

Multi-Layer Perceptron (ReLU) Details

Network Architecture

784 input units → 32 hidden units with Rectified Linear Unit (ReLU) activation → 10 output units with Softmax. Trained via hand-written backpropagation with mini-batch SGD.

h = max(0, W_1 · x + b_1)
logits = W_2 · h + b_2
∂L/∂logits = p - y
∂L/∂W_1 = ((∂L/∂logits · W_2) ⊙ [h > 0]) ⊗ x

Why ReLU?

Unlike Sigmoid (which saturates and slows gradients down), ReLU preserves strong gradient signals for active hidden features, converging much faster and reaching ~93% to 96% accuracy with just 32 units.
